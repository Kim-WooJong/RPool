# Step 10 — Metadata / crypt / legacy compatibility

Completed 2026-09-24; no version bump or remote data migration.

## Findings and fixes

Expert audit confirmed unchanged content-root encoding and raw runtime address binding.
It identified a pre-existing contract gap, not a proven pivot regression: recover and
explicit replicate reserialized parsed JSON. Added raw source loading and byte-preserving
replication API; CLI uses it. Recovery validates root/archive id then persists the original
bytes from a same-directory NamedTempFile. Generated/modified manifests still serialize
intentionally. Existing semantic fingerprint and version-specific command support stay intact.
Recovery replacement is not fsync/crash durability; Unix tempfile permissions are restrictive.

See step10-baseline-audit.json for paths and SHA-256. No portable JSON/vault schema,
secret generation/restore, root encoding or models changed. Legacy and native volume keys
remain separate. No MetadataStore stub or production native route was introduced.
ADR-003 blocking conditions remain unresolved; no distributed guarantees claimed.

Three fixed synthetic fixtures: v1 omitted defaults, v2 uncoded, v2 RS.
Expected roots independently encoded from documented LE domains, not generated by the
production functions under test. Four tests check fixed roots/defaults/exact strings,
real registry-backed logical reads, absence of new runtime fields, raw replication/recovery,
unchanged sources, invalid-input destination preservation and root inclusion/exclusion.
No real user legacy bytes were rewritten. Rollback concerns source/config compatibility,
not automatic rollback of remote data.
