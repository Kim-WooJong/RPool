# ADR-005 — Native prototype와 암호화 활성화 gate

- 상태: 확정 (Main Update 1)
- 근거: MASTER_PROMPT §4 ADR-005, §3.2, §9
- 관련: ADR-004, ADR-006

## 결정

- M1에서 **native crypto를 구현하지 않는다**.
- 따라서 OpenDAL prototype은 **test-only 또는 명시적 experimental 경로**로 제한한다.
- Local/Memory/외부 계정 없는 OpenDAL Fs·Memory로 **synthetic data**만 다룬다.
- production cloud destination으로 raw native write를 라우팅하지 않는다.
- native cloud upload를 GUI의 정상 사용 가능한 선택지로 노출하지 않는다.
- raw native adapter가 존재해도 **정상 archive write entry point는 검증된
  encryption binding을 요구한다**.
- 정책 근거 없는 `encrypted: true` boolean이나 사용자가 끌 수 있는 security bypass를
  만들지 않는다.
- local-only 테스트 backend를 열기 위해 legacy production 보호를 완화하지 않는다.

## 결과 (실행 규칙)

- legacy 암호화 데이터는 **rclone adapter를 통해 계속 읽고 쓴다**.
- legacy `Shard.blake3`와 shard size는 **crypt가 외부로 노출하는 논리 shard bytes 기준**이다.
- raw backing의 ciphertext size/hash를 그 값과 직접 비교하거나
  ciphertext를 plaintext shard로 해석하지 않는다.
- 기존 crypt key나 obscured string을 새 native key로 변환할 수 있다고 가정하지 않는다.
- native encryption의 향후 ADR에는 AEAD, nonce 수명, authenticated metadata,
  chunk/range 경계, plaintext/ciphertext hash 구분, EC와 암호화 순서,
  key export/rotation을 포함한다.
- Volume key, backend credential, metadata key는 개념적으로 분리하며
  **provider token을 volume key에서 유도하지 않는다**.

## 반론/한계

- 기존 구조는 shard 단위 rclone crypt와 연결되어 있으므로
  새 포맷과 자동 호환된다고 가정하지 않는다.
- OpenDAL prototype은 feature-gated + default-off. native 실사용 활성화와 구별한다.
