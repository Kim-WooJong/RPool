# ADR-006 — rclone optional의 정확한 의미

- 상태: 확정 (Main Update 1)
- 근거: MASTER_PROMPT §4 ADR-006, §3.2
- 관련: ADR-004, ADR-005

## 결정

- M1 종료 시 목표는 **core의 byte I/O 계약이 rclone에 종속되지 않는 것**이다.
- Local/Memory/native prototype 경로는 **rclone binary 없이 구성 가능**해야 한다.
- 그러나 **기존 crypt archive를 이용하는 작업과 crypt portability에는 계속 rclone이
  필요할 수 있다**.
- 이를 "rclone 완전 제거" 또는 "기존 사용자도 rclone 불필요"로 보고하지 않는다.

## 결과 (실행 규칙)

- rclone은 **외부 binary adapter로만 사용한다**. Go FFI이나 Go library를 core에 넣지 않는다.
- 선택적 backend는 **실패한 쓰기를 다른 주소 체계로 자동 재시도하는 failover를 뜻하지 않는다**.
- 같은 데이터·key·encryption mapping을 보장하지 못하는 **native↔rclone 자동 전환은 금지**한다.
- rclone adapter의 조건부 쓰기는 실제 검증 전까지 **Unsupported**다.
- doctor의 `rclone version` probe는 **tool diagnostic**이며, native-only/test backend
  구성에서 무조건 실행하지 않는다(Step 8에서 gate).

## 반론/한계

- "rclone optional"은 "rclone 제거"가 아니다.
- legacy crypt archive 접근과 crypt portability는 rclone 의존을 유지한다.
- native↔rclone 자동 전환은 encryption mapping identity가 증명되기 전까지 금지.
