# ADR-003 — Consistency authority를 뒤로 미루지 않음

- 상태: 확정 (Main Update 1, M1에서는 문서화만)
- 근거: MASTER_PROMPT §4 ADR-003
- 관련: ADR-002

## 결정

M1에서 아래 8가지를 명시한다(M1에서 production commit engine을 구현하라는 뜻이 아님):

1. 모든 writer가 공유하는 **하나의 권위 있는 commit 지점**이 필요하다.
2. 단일 object의 조건부 쓰기 지원과 여러 object / 여러 cloud에 걸친 원자성은 다르다.
3. generation을 읽고 비교한 다음 일반 overwrite하는 방식은 **CAS가 아니다**.
4. 서로 다른 cloud의 generation을 각각 증가시키면 **split-brain을 막지 못한다**.
5. lease만으로는 부족하며, 추후 **fencing / conditional update의 강제 지점**이 필요하다.
6. 미래 초기 native volume은 검증된 coordination이 생기기 전 **multi-writer를 광고하지 않는다**.
7. single-writer를 실제 보장하지 못하면 **사용 제한을 문서화**하고 위험한 쓰기를 허용하지 않는다.
8. metadata authority failover, quorum protocol, offline multi-master는
   **별도 설계·검증 전까지 금지**한다.

## 권장 초기 모델 (M2 후보, M1 구현 아님)

- immutable data/metadata 객체를 올린 뒤, **단일 authority의 작은 root pointer를
  조건부 갱신**하는 방식.
- 미래 설계에는 commit 성공 후 응답 유실, pending/orphan upload, 명시적 durability
  조건, reader와 GC 경합을 포함한다.
- metadata replica는 backup일 수 있지만 **자동으로 consensus member가 되지 않는다**.

## M1 blocking 조건 (MetadataStore 구현 전 충족 필요)

- one writer-shared commit authority
- root pointer + immutable layout
- real conditional CAS (read/compare/overwrite가 아님)
- fencing + lease enforcement
- commit visibility/durability + lost-response idempotency
- orphan/pending lifecycle
- reader/GC race protocol
- stale/offline conflict policy
- replica backup-vs-consensus role + recovery
- enforceable single-writer 또는 refusal
- separately designed failover/quorum/offline multi-master
- capability/unknown-outcome behavior

## 반론/한계

- M1에서 이 항목을 "완료"로 표시하면 안 된다. 문서화만 한다.
- Local/Memory CAS가 위 blocking 조건을 만족하지 않는다.

## Step 10 재확인

2026-09-24: production MetadataStore/commit authority는 도입하지 않았다.
Legacy manifest가 현재 authority이며 replica는 backup이다. OpenDAL Memory는
테스트 전용이다. Generation 및 process-local conditional create는 분산 CAS나
single-writer enforcement의 증거가 아니다. 위 조건은 다음 업데이트에서도 미해결이며
검증된 authority/encryption binding 없이 native volume writes를 활성화하지 않는다.
